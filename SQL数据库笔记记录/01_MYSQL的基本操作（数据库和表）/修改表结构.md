一、 修改表结构用啥？（一句话理解）
表建好之后想改名字、改字段、加列删列，统统用 ALTER TABLE 这一个命令家族搞定。

二、 怎么修改表名？（实操代码）

ALTER TABLE 旧表名 RENAME TO 新表名;
-- 举例：
ALTER TABLE employees RENAME TO emp;
-- 还有一种等价写法 RENAME TABLE（我实际用的就是这种，还能一次改多张表）：
RENAME TABLE 旧表名 TO 新表名;
-- 举例（我在 Navicat 里真实执行过的）：
RENAME TABLE `shlg`.`employees` TO `shlg`.`employees1`;

三、 怎么修改列名？（两种写法）

-- 方法一：CHANGE（老写法，必须带上原数据类型，不推荐）
ALTER TABLE 表名 CHANGE COLUMN 旧列名 新列名 数据类型;
-- 方法二：RENAME COLUMN（MySQL 8.0 推荐写法，不需要带类型，更安全）
ALTER TABLE 表名 RENAME COLUMN 旧列名 TO 新列名;
-- 举例：
ALTER TABLE emp RENAME COLUMN employee_name TO emp_name;

四、 怎么修改列？（MODIFY COLUMN 不止能改类型）

ALTER TABLE 表名 MODIFY COLUMN 列名 新数据类型;
-- 举例（把工资的精度改大一点）：
ALTER TABLE emp MODIFY COLUMN salary DECIMAL(10,2);

-- 重点：MODIFY 是“整列重建”，除了类型，还能顺便改 是否允许NULL / 自增 / 列的位置！
-- （我在 emp1 表上把这几种用法全都实战过一遍，见下面第七节实录）
ALTER TABLE 表名 MODIFY COLUMN 列名 类型 NOT NULL;                    -- 加非空约束
ALTER TABLE 表名 MODIFY COLUMN 列名 类型 NOT NULL AUTO_INCREMENT;      -- 加自增
ALTER TABLE 表名 MODIFY COLUMN 列名 类型 FIRST;                       -- 把列移到最前面
ALTER TABLE 表名 MODIFY COLUMN 列名 类型 AFTER 另一列;                -- 把列移到某列后面

五、 怎么添加新列？

ALTER TABLE 表名 ADD COLUMN 新列名 数据类型;
-- 举例（默认加在最后面）：
ALTER TABLE emp ADD COLUMN age INT;
-- 进阶：指定加在某个列后面（AFTER）或者加在最前面（FIRST）
ALTER TABLE emp ADD COLUMN gender CHAR(1) AFTER emp_name;

六、 怎么删除指定列？（小心踩坑）

ALTER TABLE 表名 DROP COLUMN 列名;
-- 举例：
ALTER TABLE emp DROP COLUMN age;

**新手必踩大坑**：DROP COLUMN 会把这一列的数据全部删掉，无法恢复！另外 MODIFY 修改类型时，如果新类型比原来“小”（比如 VARCHAR(20) 改成 VARCHAR(5)），已有数据可能被截断，改之前先确认数据情况。

七、 我的 Navicat 真实操作实录（2026-09-22 / 09-28，对象是 shlg.emp1 表）

我对 emp1（字段：employee_id、emp_name、salary、dept_id）反复做过下面这些改造，全部是真实执行过的语句：

-- ① 9月28日 19:27 给 employee_id 加 NOT NULL，并把它移到第一列（FIRST）
ALTER TABLE `shlg`.`emp1`
    MODIFY COLUMN `employee_id` int(11) NOT NULL FIRST;

-- ② 19:27 继续加自增，同时把 emp_name 排到 employee_id 后面（AFTER）：一条 ALTER 里可以堆多个 MODIFY，用逗号分隔
ALTER TABLE `shlg`.`emp1`
    MODIFY COLUMN `employee_id` int(11) NOT NULL AUTO_INCREMENT FIRST,
    MODIFY COLUMN `emp_name` varchar(40) CHARACTER SET utf8 COLLATE utf8_general_ci NULL AFTER `employee_id`;

-- ③ 19:31 补加主键（注意：我是先有 AUTO_INCREMENT 再 ADD PRIMARY KEY 的，自增列必须先有索引，而加主键正好提供了索引）
ALTER TABLE `shlg`.`emp1`
    MODIFY COLUMN `employee_id` int(11) NOT NULL AUTO_INCREMENT FIRST,
    ADD PRIMARY KEY (`employee_id`);

-- ④ 19:32 反悔了，删主键（删之前先把 AUTO_INCREMENT 去掉，否则报错，套路和《主键约束》笔记里那条坑完全对应）
ALTER TABLE `shlg`.`emp1`
    MODIFY COLUMN `employee_id` int(11) NOT NULL FIRST,
    DROP PRIMARY KEY;

-- ⑤ 19:32 把 emp_name、salary 也改成 NOT NULL，顺便用 AFTER 调整列顺序
ALTER TABLE `shlg`.`emp1`
    MODIFY COLUMN `emp_name` varchar(40) CHARACTER SET utf8 COLLATE utf8_general_ci NOT NULL AFTER `employee_id`,
    MODIFY COLUMN `salary` float(8, 2) NOT NULL AFTER `emp_name`;

每次改完我都用 SHOW FULL COLUMNS FROM `emp1`; 确认结构真的变了，这个“改一下 → 查一下”的节奏建议保持。

**我自己总结的经验**：改表结构时 Navicat 的“设计表”界面最终生成的也是这些 ALTER 语句，在查询编辑器里亲手写一遍比点界面印象深得多。另外 MODIFY 是“整列重建”，写它的时候要把这一列最终的完整定义（类型 + NULL 属性 + 字符集 + 位置）一次性写全，漏写了就会被恢复成默认值（比如忘了写 NOT NULL，列就变回允许空）。
