一、 主键是个啥？（一句话理解）
主键就是一张表里的“身份证号”。它的作用就是唯一标识表里的某一行数据。

二、 主键的“三大铁律”（一定要背下来）
不能重复：比如学生表，学号是主键，那就不能有两个学号一样的学生。

不能为空（NULL）：必须有值，不能空着。

一张表只能有一个主键（但可以是由多个字段组合成的“复合主键”）。

三、 怎么加主键？（实操代码）
1. 建表的时候顺手加上（推荐，最常用）

单列主键（最常用）：

CREATE TABLE emp (
    id INT PRIMARY KEY,  -- 直接跟在字段后面
    name VARCHAR(20)
);

复合主键（多列一起做主键）：

CREATE TABLE student_course (
    stu_id INT,
    course_id INT,
    score FLOAT,
    PRIMARY KEY (stu_id, course_id)  -- 写在最后，两列一起做主键
);
2. 表已经建好了，想补加主键（用 ALTER）：

ALTER TABLE emp ADD PRIMARY KEY (id);

四、 怎么删主键？（小心踩坑）

ALTER TABLE emp DROP PRIMARY KEY;

 新手必踩大坑：如果你的主键带了 AUTO_INCREMENT（自增），直接删主键会报错！必须先用 ALTER TABLE emp MODIFY id INT; 把自增属性去掉，然后再删主键。

五、 我的 Navicat 真实操作实录（2026-09-22 / 09-28，shlg 库）

实录 1：建表时主键列忘了 NOT NULL（9月22日，建 employee2 表）

我第一版建表把所有字段都写成了 NULL：

CREATE TABLE `shlg`.`employee2` (
    `employee_id` int NULL,          -- 问题就在这：主键列允许 NULL
    `employee_name` varchar(10) NULL,
    `salary` float(8, 2) NULL,
    PRIMARY KEY (`employee_id`)
);

当场报错，原文是：
All parts of a PRIMARY KEY must be NOT NULL; if you need NULL in a key, use UNIQUE instead
翻译过来就是：主键的每一部分都必须 NOT NULL；如果你真想让它可以空，那就用 UNIQUE 键，别用主键。第二版把字段改成 NOT NULL 后建表成功，印证了“三大铁律”里那条“不能为空”。

实录 2：给已建好的 emp1 表补主键、删主键（9月28日）

-- 补主键（先有自增再加主键，一条 ALTER 里同时写）：
ALTER TABLE `shlg`.`emp1`
    MODIFY COLUMN `employee_id` int(11) NOT NULL AUTO_INCREMENT FIRST,
    ADD PRIMARY KEY (`employee_id`);

-- 删主键（删之前先用 MODIFY 把 AUTO_INCREMENT 去掉，否则报错）：
ALTER TABLE `shlg`.`emp1`
    MODIFY COLUMN `employee_id` int(11) NOT NULL FIRST,
    DROP PRIMARY KEY;

这两句我是真的按“先去自增 → 再删主键”的顺序操作成功的，和上面那条大坑完全对应。反过来加主键时也要注意：AUTO_INCREMENT 列必须先是某张索引的首列，所以实践里常见“MODIFY 加自增”和“ADD PRIMARY KEY”写在同一条 ALTER 里一次生效。

另外提醒：补主键前这一列必须已经有数据不重复且没有 NULL，否则 MySQL 会拒绝。我在 emp1 上能顺利加主键，是因为 employee_id 当时刚好满足这两个条件。
