# 外键约束

## 一、外键是个啥？（一句话理解）

外键就是把两张表关联起来的"牵线绳"，保证填进去的关联数据真实存在。比如员工表 emp 里的 dept_id 指向部门表 dept 的主键 id，意思是"这个员工必须属于某个真实存在的部门"。

## 二、外键的三大铁律

1. 被引用的那一列，必须是另一张表的主键（或唯一键）
2. 外键列和被引用列的数据类型要一致
3. 外键的值必须是父表里已有的值，或者为 NULL（父表=被引用的表，子表=有外键的表）

## 三、怎么加外键？

```sql
-- 建表时加上
CREATE TABLE dept (
    id INT PRIMARY KEY,
    dept_name VARCHAR(20)
);

CREATE TABLE emp (
    id INT PRIMARY KEY,
    name VARCHAR(20),
    dept_id INT,
    FOREIGN KEY (dept_id) REFERENCES dept (id)
);

-- 表建好了再补加
ALTER TABLE emp ADD FOREIGN KEY (dept_id) REFERENCES dept (id);

-- 进阶：起个约束名（方便以后删除），并设置级联规则
ALTER TABLE emp ADD CONSTRAINT fk_emp_dept FOREIGN KEY (dept_id)
    REFERENCES dept (id)
    ON DELETE CASCADE    -- 父表记录被删时，子表相关记录跟着删
    ON UPDATE CASCADE;   -- 父表主键被改时，子表外键跟着改
```

## 四、怎么删外键？

```sql
-- 删外键要用"约束名"，不是列名
ALTER TABLE emp DROP FOREIGN KEY fk_emp_dept;

-- 建表时没起名，MySQL 会自动生成（如 emp_ibfk_1），先查再删
SHOW CREATE TABLE emp;
```

## 五、新手必踩大坑

1. 删外键必须用约束名，写成 `DROP FOREIGN KEY (dept_id)` 会报错。
2. 建外键报 `Cannot add foreign key constraint`，多半是：引擎不是 InnoDB、类型不一致、被引用列不是主键/唯一键。
3. 父表被子表引用时删不掉，要么先删子表数据，要么建外键时设好 `ON DELETE CASCADE`。
