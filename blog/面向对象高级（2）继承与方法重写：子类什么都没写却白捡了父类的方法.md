## 这次要证明的事

继承我早就会写，`class 子类(父类):` 就完事了。但这一节有个具体的任务，逼我把"继承到底继承了什么"搞清楚：

父类 `Car` 有一个公共方法 `charge()`，输出「xxx正在补充燃料」。然后我要依次验证：

1. 子类**一行代码都不写**，能不能直接调 `charge()`？
2. 子类把 `charge()` 重写掉之后，父类那个版本还能不能救回来？
3. 父类的私有车主名 `__owner`，到底有没有跟着继承下来？

## 先说一个卡了我半天的问题：父类 import 不进来

`Car` 定义在 `1.封装.py` 里。我打算在新文件里这么写：

```python
from 1.封装 import Car   # SyntaxError
```

直接语法报错。原因是这个文件名太特殊了：**有点号，还有中文**。Python 的 `import` 语句里的点号是"包层级"的意思，`1.封装` 会被拆成「找一个叫 `1` 的包，里面有个模块叫 `封装`」——它先去猜 `1` 是个包，第一秒就崩了，根本轮不到中文出问题。

我不想为了 import 去改文件名（这一章所有文件都是「数字 + 点 + 中文名」的统一命名），所以改成**按文件路径读源码、直接执行**的方式：

```python
import pathlib
from typing import Any

namespace: dict[str, object] = {"__name__": "fengzhuang_demo"}
parent_file = pathlib.Path(__file__).with_name("1.封装.py")
exec(compile(parent_file.read_text(encoding="utf-8"), str(parent_file), "exec"), namespace)

Car: Any = namespace["Car"]
```

三个细节值得记一下：

**① `pathlib.Path(__file__).with_name(...)`**：用「跟本文件同目录」定位父类文件，不管你从哪个工作目录运行都能找到。我之前用相对路径，换个工作目录就 `FileNotFoundError`。

**② namespace 里要塞 `__name__`**：`exec` 执行的是一段源码，它需要一个"模块命名空间"当容器。`1.封装.py` 里没有依赖 `__name__` 的语句，但这个键是模块环境的标配，给一个假名字（`fengzhuang_demo`）能避免后续踩坑。代价是：**执行它会顺带把父类文件里那些演示 `print` 全跑一遍**，所以运行时开头会先刷出一串封装演示的输出，再接继承演示。这一点我在注释里标清楚了。

**③ `Car: Any = namespace["Car"]` 这里的 `Any` 不是偷懒**：`namespace` 声明成 `dict[str, object]`，取出来的东西检查器只能认定是 `object`。如果我把注解写成 `Car: type = namespace["Car"]`，反而会引发**连锁误判**——下面 `class FuelCar(Car):` 和 `super().__init__()` 会被检查器按元类重载 `type(name, bases, dict, **kwds)` 去匹配，凭空冒出一堆新告警。用 `Any` 承接，`Any` 不参与重载校验，世界清净。

这里踩的教训是：**修类型告警时，最危险的不是原来那条告警，而是你为了消它写进去的新代码又带来了第二条。**

## 正式代码

```python
# by tryer07 ｜ Python 面向对象高级（2）继承与方法重写 · 学习笔记
import pathlib
from typing import Any

namespace: dict[str, object] = {"__name__": "fengzhuang_demo"}
parent_file = pathlib.Path(__file__).with_name("1.封装.py")
exec(compile(parent_file.read_text(encoding="utf-8"), str(parent_file), "exec"), namespace)
Car: Any = namespace["Car"]


# 验证一：一个"什么都没写"的空子类
class TempFuelCar(Car):
    pass


temp = TempFuelCar("宝马", "X5", "黑色", "张三")
temp.charge()          # 类里一个字都没写，却直接调到了父类的方法


# 正式的燃油车子类：重写 charge()，并在重写里回头调用父类版本
class FuelCar(Car):
    # 重写 __init__ 时必须先 super().__init__() 初始化父类属性
    def __init__(self, brand, model, color, owner, tank_size):
        super().__init__(brand, model, color, owner)
        self.tank_size = tank_size

    @staticmethod
    def refuel():
        print("去加油站加油")

    # 方式一：super().charge() 先执行父类 charge()，再执行子类代码
    def charge(self):
        super().charge()
        print(f"{self.brand}{self.model}正在加油")

    # 方式二：Car.charge(self) 显式点名父类方法，必须把 self 传进去
    # （同一个类里不能有两个同名 charge，所以另起一个名字单独演示）
    def charge_v2(self):
        Car.charge(self)
        print(f"{self.brand}{self.model}正在加油（方式二：Car.charge(self)）")

    def get_owner(self):
        # 占位重写：演示方法重写会替换掉父类实现
        return f"子类重写的脱敏接口（占位，油箱 {self.tank_size} 升）"


# 电车类也重写 charge()，改成电车逻辑
class ElectricCar(Car):
    def __init__(self, brand, model, color, owner, battery):
        super().__init__(brand, model, color, owner)
        self.battery = battery

    def charge(self):
        print(f"{self.brand}{self.model}正在充电")


bmw = FuelCar("宝马", "X5", "黑色", "张三", 68)
bmw.charge()
bmw.charge_v2()

fuel = FuelCar("奥迪", "A6", "黑色", "外收内放", 58)
electric = ElectricCar("特斯拉", "Model 3", "白色", "外收内放", 60)

print("车主（fuel 重写版）:", fuel.get_owner())
print("车主（electric 继承父类原版）:", electric.get_owner())
try:
    print(getattr(fuel, "__owner"))
except AttributeError as e:
    print("【验证】私有属性不会作为子类属性被继承:", e)

print("fuel 是 Car 的实例吗:", isinstance(fuel, Car))
print("ElectricCar 是 Car 的子类吗:", issubclass(ElectricCar, Car))

# 不同子类各调各的 charge()
fuel.charge()
electric.charge()
```

## 三个结论

**一、空子类真的能白捡方法。** `TempFuelCar` 的类体就一个 `pass`，调 `temp.charge()` 却打出了「宝马X5正在补充燃料」。这就是继承最原始的样子：子类不需要重新实现父类已经写好的能力。

**二、重写之后，父类版本靠 `super()` 或点名抢救。**

两种写法我都跑了，输出都是「先补充燃料、再加油」：

- `super().charge()` —— 不关心父类叫什么，沿继承链往上找。
- `Car.charge(self)` —— 显式点名，但**必须手动把 `self` 传进去**。

第二种是我最容易写错的地方。`Car.charge(self)` 是"通过类拿到未绑定方法，自己把实例塞进去"，写成 `Car.charge()` 会直接抱怨缺少参数 `self`。而 `super().charge()` 里的 `super()` 已经替我把当前实例传好了，所以不写 `self`。这两种方式的参数规则是相反的，记混就报错。

**三、私有属性不会作为"子类自己的属性"被继承。**

`fuel` 是 `FuelCar` 的对象，我用 `getattr(fuel, "__owner")` 去取，报 `'FuelCar' object has no attribute '__owner'`。

但注意，`electric.get_owner()` 明明正常打出了 `*收内放`。这说明**父类的方法内部照样能用 `self.__owner`，属性本身也确实存在于对象上**（它被改名成了 `_Car__owner`），只是"以 `__owner` 这个名字、在子类作用域里"访问不到。

所以准确的说法是：私有成员不是"没继承"，而是"继承了但子类够不着原名"。这一字之差我以前一直讲错。

## 我踩的那个蠢坑

上面这些代码我之前写的是另一个版本，`FuelCar.__init__` 里多出来三行：

```python
def __init__(self, brand, model, color, owner, tank_size):
    super().__init__(brand, model, color, owner)
    self.color = None
    self.model = None
    self.brand = None
    self.tank_size = tank_size
```

跑出来是这样：

```
brand: None | model: None | color: None
奥迪A6正在补充燃料
NoneNone正在加油
```

`super().__init__()` 老老实实把父类属性初始化好了，紧接着我用三行 `= None` 把它们全铲了。更坑的是，父类 `charge()` 用的正是 `self.brand + self.model`，于是拼接结果成了 `NoneNone正在加油`——不是报错，而是安静地给你一坨垃圾。

我当时以为是重写机制有问题，回来反复读了三遍才明白：**重写 `__init__` 只有一件事是你必须做的，就是先调 `super().__init__()` 把父类的属性交还给它；剩下的行如果同名覆盖，父类继承来的属性就等于白初始化了。**

我最初写这三行是想"验证子类可以覆盖父类属性"，这个验证本身没错，但把它留在正式演示代码里，就会污染后面所有输出。这也是为什么第 2 篇（`2.继承.py`）里我保留了这几行 `= None` 的试验，而到了第 3 篇（`3.继承（方法重写）.py`）我把它们删掉了——**同一份代码，用来"验证破坏力"和用来"验证正常行为"，不能混在一起。**

## 小结

1. 子类什么都不写，也能直接调用父类的公共方法，这是继承的本体。
2. 重写只影响"子类对象调用时执行哪个版本"，父类版本可以用 `super().方法()` 或 `父类名.方法(self)` 请回来，后者的 `self` 必须手写。
3. 私有属性在对象上真实存在，只是子类作用域里按原名取不到；父类自己的方法内部照常能访问。
4. 重写 `__init__` 时不要同名覆盖父类刚初始化好的属性，否则会得到 `NoneNone正在加油` 这种不报错的错误。
5. 文件名带点号或中文时 `import` 会失败，`pathlib + exec + Any 承接` 是一条不改文件名的路。
