## 案例名称：《书海灯塔 · 命令行图书借阅系统》

老师给的需求清单很朴素：会员凭卡号密码登录，登录后可以借书、还书、查看自己的借阅，数据存 JSON。

但里面藏着一条**专门为多态准备**的规则：

- 普通会员最多借 **3** 本。
- VIP 会员最多借 **6 + VIP 等级** 本，等级没指定就按 1 算。
- 图书可用数量大于 0 才能借；借出一本可用数减 1，归还一本加 1。
- 已经借满的人不能再借。

我一看到"不同会员上限不同"就明白了：这就是上一篇的 `member.get_max_borrow()`，绝对不该写成 `if type(member) == VIPMember`。

## 类结构

我最后设计了五个类，职责分成两层：

**业务对象层**负责"是什么"。`Book` 图书类封装编号、标题、作者、总数、可用数和借还动作；`Member` 会员父类封装私有的卡号、密码、姓名，加上公共的借阅记录；`NormalMember` 和 `VIPMember` 继承它，各自重写借阅上限。

**系统层**负责"怎么运作"。`LibrarySystem` 管 JSON 读写、登录、菜单循环、借书、还书、查看借阅，它只跟 `Member` 这个父类类型打交道，压根不知道有几种会员。

会员这一支正好把整章串了一遍：卡号密码用 `__` 私有化（封装），两个子类继承父类（继承），上限方法各自重写、系统只调父类签名（多态）。

那个 `type` 字段是我特意加的：读回来时靠它决定该 new 哪个子类。而 `borrowed_ids` 只存图书编号、不存整本书的信息——这是**避免同一份图书数据被复制两份**，改库存时不会出现"张三手里那本《三体》还剩几本"和图书馆说的不一致。

## 会员这一支：封装 + 继承 + 多态全在里面

```python
# by tryer07 ｜ Python 面向对象高级（5）综合实战 · 学习笔记


class Book:
    # 参数与数值属性都显式标注 int/str：避免无注解参数经 min() 推导出
    # SupportsDunderLT/GT 联合类型，导致布尔/整数返回处报类型不符
    def __init__(self, book_id: str, title: str, author: str, total: int, available: int):
        self.book_id = book_id
        self.title = title
        self.author = author
        self.total: int = total
        # 可用数量不得大于总数量
        self.available: int = min(available, total)

    def is_available(self) -> bool:
        return self.available > 0

    def borrow(self) -> None:
        self.available -= 1

    def return_back(self) -> None:
        # 归还以总数量为上限做保护，防止还出"超库存"的脏数据
        self.available = min(self.available + 1, self.total)

    def to_dict(self) -> dict:
        return {"book_id": self.book_id, "title": self.title, "author": self.author,
                "total": self.total, "available": self.available}


class Member:
    # 卡号、密码、姓名全部私有：外部只能通过接口读，且没有修改入口
    def __init__(self, card_no: str, password: str, name: str):
        self.__card_no: str = card_no
        self.__password: str = password
        self.__name: str = name
        self.borrowed_books: list[Book] = []

    def get_card_no(self) -> str:
        return self.__card_no

    def get_name(self) -> str:
        return self.__name

    # 密码不返回，只回答"校验是否通过"
    def check_password(self, password: str) -> bool:
        return password == self.__password

    # 最大可借数量：父类不定义具体规则，交给子类重写
    def get_max_borrow(self) -> int:
        return 0

    def is_borrow_full(self) -> bool:
        return len(self.borrowed_books) >= self.get_max_borrow()

    def to_dict(self) -> dict:
        return {
            "type": "normal",
            "card_no": self.__card_no,
            "password": self.__password,
            "name": self.__name,
            "borrowed_ids": [book.book_id for book in self.borrowed_books],
        }


class NormalMember(Member):
    def get_max_borrow(self) -> int:
        return 3


class VIPMember(Member):
    def __init__(self, card_no: str, password: str, name: str, vip_level: int = 1):
        super().__init__(card_no, password, name)
        self.__vip_level: int = vip_level

    def get_vip_level(self) -> int:
        return self.__vip_level

    def get_max_borrow(self) -> int:
        return 6 + self.__vip_level

    # 在父类公共字段之上补充 VIP 专属字段
    def to_dict(self) -> dict:
        data = super().to_dict()
        data["type"] = "vip"
        data["vip_level"] = self.__vip_level
        return data
```

几个我比较满意的设计点：

**`Member.get_max_borrow()` 故意返回 0。** 父类不知道该定多少，但必须有个方法占住这个位置，否则 `is_borrow_full()` 里调 `self.get_max_borrow()` 就会 AttributeError。返回 0 意味着"父类对象一本都借不了"，把"必须由子类给出真实规则"这件事变成了硬约束。

**`is_borrow_full()` 写在父类，一行都没重复。** 判断逻辑（已借数量 ≥ 上限）对两种会员完全一样，只有上限数值不同。所以父类实现逻辑、子类只提供数字——**这是我这一章学到的"继承该怎么用"最实在的样子：共性上提，差异下放到重写点。**

**`VIPMember.to_dict()` 用 `super().to_dict()` 打底再补字段。** 父类已经把四个公共字段拼好了，子类只加 `type` 和 `vip_level`。要是我在子类里重新写一遍全部字段，将来父类加一个字段就得记得来两个子类各补一次。

**密码是私有的，但写进 JSON 时又需要它。** 所以 `to_dict()` 是**类内部**方法，它能读 `self.__password`（第 1 篇就验证过：私有属性在类内部照常可用）。外部则永远只能问 `check_password()` 一个"对不对"，拿不到原文。

## 系统层：它不知道自己服务几种会员

```python
class LibrarySystem:
    def __init__(self):
        # 编号 -> 对象 的索引，O(1) 查找
        self.books: dict[str, Book] = {}
        self.members: dict[str, Member] = {}

    def load_data(self) -> None:
        self._ensure_data_file("books.json", _DEFAULT_BOOKS)
        self._ensure_data_file("members.json", _DEFAULT_MEMBERS)

        for item in self._read_json("books.json"):
            book = Book(item["book_id"], item["title"], item["author"], item["total"], item["available"])
            self.books[book.book_id] = book

        for item in self._read_json("members.json"):
            # 靠 type 字段决定实例化成哪个子类
            if item["type"] == "vip":
                member: Member = VIPMember(item["card_no"], item["password"],
                                           item["name"], item.get("vip_level", 1))
            else:
                member = NormalMember(item["card_no"], item["password"], item["name"])
            # 在借记录按图书编号还原为 Book 对象引用
            for book_id in item.get("borrowed_ids", []):
                if book_id in self.books:
                    member.borrowed_books.append(self.books[book_id])
            self.members[member.get_card_no()] = member

    def borrow_book(self, member: Member) -> None:
        # 先展示库存列表，再验上限、验编号、验库存
        if member.is_borrow_full():
            print(f"借阅失败：{member.get_name()} 已借 {len(member.borrowed_books)} 本，"
                  f"达到最大可借数量（{member.get_max_borrow()} 本），请先归还再继续借阅")
            return

        book_id = input("请输入要借阅的图书编号（输0取消）：").strip()
        target_book = self.books.get(book_id)
        if target_book is None:
            print("借阅失败：图书编号不存在，请核对后重试")
            return
        if not target_book.is_available():
            print(f"借阅失败：《{target_book.title}》可用数量为 0，暂无库存可借")
            return

        target_book.borrow()
        member.borrowed_books.append(target_book)
        self.save_data()
        print(f"借阅成功：{member.get_name()} 成功借阅《{target_book.title}》，"
              f"该馆尚余 {target_book.available} 本，您已借 {len(member.borrowed_books)}"
              f"/{member.get_max_borrow()} 本")

    def run(self) -> None:
        self.load_data()
        member = self.login()          # 未登录返回 None，直接结束
        if member is None:
            print("已退出系统，再见！")
            return
        print(f"登录成功，欢迎 {member.get_name()}！您最多可借阅 {member.get_max_borrow()} 本")
        while True:
            self.show_menu()
            choice = input("请输入功能编号：").strip()
            if choice == "1":
                self.borrow_book(member)
            elif choice == "2":
                self.return_book(member)
            elif choice == "3":
                self.show_borrowed(member)
            elif choice == "0":
                print("已退出图书借阅系统，欢迎再次光临！")
                break
            else:
                print("输入有误，请输入 0/1/2/3 对应的编号")
```

`login()` 的返回值是 `Member | None`：卡号或密码错就循环重问，输 `0` 就返回 `None`。这里有个规则落地的方式我挺喜欢——"只有登录成功才能访问系统"不是靠一个 `is_logged_in` 标志位到处判断，而是靠**没有 member 对象就根本进不到菜单循环**这条结构约束。想绕过都拿不到入场券。

`return_book()` 和 `show_borrowed()` 我就不贴全了，逻辑分别是：只在**自己的** `borrowed_books` 里找编号（找不到就提示"该编号不在您的借阅记录中"，杜绝归还别人书或凭空造书），以及按 `enumerate(..., start=1)` 打序号列表。

## 踩到的三个坑

**坑一：一行没有注解的 `min()`，让三处八竿子打不着的代码一起报错。**

`Book` 最初我是这么写的：

```python
def __init__(self, book_id, title, author, total, available):
    self.total = total
    self.available = min(available, total)
```

然后 PyCharm 在三个地方分别给了告警：

```
第51行  应为类型 'bool'，但实际为 'SupportsBool'
第55行  应为类型 'int'，但实际为 'SupportsDunderLT[Any] | SupportsDunderGT[Any]'
第59行  应为类型 'int'，但实际为 'SupportsDunderLT[Any] | SupportsDunderGT[Any]'
```

这三行分别是 `return self.available > 0`、`self.available -= 1`、`self.available = min(self.available + 1, self.total)`。它们看着都没问题，为什么一起报错？

因为 `min()` 的参数没有类型来源，检查器只能推断成"某个支持 `<` 比较、支持 `>` 比较的未知类型"，也就是那一长串 `SupportsDunderLT | SupportsDunderGT` 协议联合类型。这个**不是 int** 的结论顺着 `self.available` 传到了所有用到它的地方：`> 0` 的返回值因此不是 `bool` 而是 `SupportsBool`，`-= 1` 和 `min(...)` 的回写也对不上 `int`。

修法不是加抑制注释，也不是 `int(...)` 强转（强转会引发新的重载误判），而是**给类型的源头标注**：参数写 `total: int, available: int`，属性写 `self.available: int = min(available, total)`。属性类型一旦确定，三个下游告警自然全部收敛。

**坑二：同一个函数里两次用 `book` 这个名字，类型冲突。**

`borrow_book` 里我先在展示循环用了 `for book in self.books.values()`，然后写：

```python
book = self.books.get(book_id)
```

mypy 立刻报错。原因是循环里的 `book` 已经被确定为 `Book`，而 `dict.get()` 返回的是 `Book | None`——同一个名字前后被推断成两个不兼容的类型。

IDE 的问题面板当时**没报这条**，是我跑 mypy 才抓出来的。改法很简单，查找结果换个名字 `target_book` 承接。这也让我养成一个习惯：循环变量用完就别再复用那个名字，尤其是接下来要接一个可空结果的时候。

**坑三：`show_borrowed(self, member)` 根本不用 `self`。**

第 1 篇我就遇到过 PyCharm 的「可降级为静态方法」提示，这次我直接照建议改了：

```python
@staticmethod
def show_borrowed(member: Member) -> None:
```

`_path(file_name)` 同理。这两个方法只是"逻辑上属于这个系统"，但不碰任何实例状态，标成静态方法更诚实。**不过要谨慎：一旦加了 `@staticmethod`，方法里就不能再用 `self`，改动前得先把方法体读一遍。**

## 系列总结

写完这五篇，我把这一章的理解收敛成五句话：

1. **封装**不是"藏起来"，是"由我决定以什么形式被暴露"，所以私有属性必须配一个对外接口。
2. **继承**的价值是共性上提、差异下放：`is_borrow_full()` 只写一遍，`get_max_borrow()` 各子类各回一个数。
3. **重写**之后父类版本靠 `super().方法()` 或 `父类.方法(self)` 抢救，后者的 `self` 必须手写；重写 `__init__` 时不要同名覆盖父类刚初始化好的属性。
4. **多继承**查找回迹是 MRO，`super()` 只代表"下一个"，第二个及以后的父类只能显式点名；顺序改变最危险的后果是参数被静默塞错，而不是报错。
5. **多态**的受益方是调用者；而 Python 的鸭子类型更进一步——不看血统看行为，`Protocol` 是给这种行为自由做标注的正统写法。

还有一个跟面向对象无关但贯穿全程的收获：**修告警要修根因，而且要验证"净零"**——消了三条旧告警、结果写进去的新代码又带来两条，等于没修。我的做法是先从类型来源和数据结构层面改，改完实际跑一遍程序，再用 IDE 面板加独立 mypy 各查一次。
