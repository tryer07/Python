# FastAPI猜字谜实战（1）跑通第一个接口：搞懂前后端分工

> 这是我跟做一款 AI 猜字谜 Web 应用系列的第一篇。整个项目叫汉字弥合，是一个 AI 主持人出题、我来猜汉字的网页小游戏。这一篇先不碰游戏，从一个最小的 Hello World 开始，把 Web 开发的门推开一条缝。

## 一、写 Python 跟做网页有啥关系

我以前写的 Python 都在黑色控制台里跑，打印点东西就结束了。可浏览器里那些页面是怎么来的，Python 又能帮上什么忙？

后来我用一个比喻想通了，就是餐厅。你坐在大厅看菜单、点菜、等上菜，这个大厅就是前端，是你在浏览器里能看到能点的界面。后厨里颠勺炒菜、真正把菜做出来的地方，就是后端。你在大厅永远看不到后厨长什么样，只管点单和吃。

Python 在这里干的就是后厨的活：接你点出来的请求，去算、去查、去调 AI，把结果做出来端给你。这一篇我做的就是最小的一个后厨。

## 二、装两个库，写六行代码

搭这个后厨我装了两个库。`fastapi` 负责接请求给响应，`uvicorn` 是个服务器，专门把我写的程序跑起来让它能被访问。

```
pip install fastapi uvicorn
```

然后新建文件 `1.FastAPI入门程序.py`，核心就六行，少得让我不敢相信这是个网站：

```
from fastapi import FastAPI
import uvicorn

app = FastAPI()

@app.get("/")
def root():
    return {"message": "Hello World"}

if __name__ == "__main__":
    uvicorn.run(app, host="0.0.0.0", port=8000)
```

一行行说我在干嘛：

- `app = FastAPI()` 建了个后厨总机，后面所有接口都挂在它身上。
- `@app.get("/")` 这个 `@` 开头的是装饰器，意思是有人访问根路径 `/` 时就执行下面的函数，`get` 代表我要取东西。
- 函数里我 `return` 一个字典。很舒服的一点是我直接写 Python 字典就行，fastapi 会自动把它变成 JSON 吐给浏览器。
- `uvicorn.run(...)` 把后厨开起来，端口用 `8000`。

## 三、跑起来后我在浏览器看到了什么

服务起来后，我在浏览器敲 `http://localhost:8000/`，屏幕上出现：

```
{"message":"Hello World"}
```

我又加了个 `@app.get("/users")`，让它返回三个人的信息。访问 `http://localhost:8000/users`，数据就整整齐齐以 JSON 显示出来了。

到这里我意识到：浏览器里显示的是一堆数据，没有任何漂亮界面。它就是后厨端出来的原始菜品，还没摆盘。摆盘也就是前端界面，是后面单独做的事。

## 四、白捡的调试神器：/docs

fastapi 会自动生成一个接口说明书页面，我在地址后面加 `/docs` 访问 `http://localhost:8000/docs` 就能看到。它把每个接口列出来，还能直接点 Try it out 再 Execute，等于不写任何前端就能在浏览器里测试接口。我测后端基本全靠它，每节课加新接口都先来这点一遍，确认通了再去想界面。

补一句边界：这页面的标题、分组、描述我能改成中文，但 Try it out、Execute 这些按钮是它固定外壳改不了。

## 五、这算前端还是后端

一句话锁死：只要是我用 Python 在这个文件里写的，全都属于后端。哪怕 `/docs` 显示在浏览器里看着像前端，那也是后端自带的调试工具。真正的前端，是后面要单独用 HTML、CSS、JavaScript 搭的那个游戏大厅。

## 六、趁热打个底：RESTful

这一篇接口都用 GET 也就是取。但后端定接口有个通用规矩叫 RESTful，后面做猜字谜就是照它设计的。核心两条，大白话记：

一是用网址定位我要动哪个东西。比如 `/api/sessions` 代表会话这堆资源，`/api/sessions/某个id` 代表其中某一个会话。

二是用请求方式说我要对它干什么。GET 读取、POST 新建、PUT 修改、DELETE 删除。同一个 `/api/sessions/某个id`，用 GET 是看这局，用 DELETE 是删这局，网址一样动作不同结果就不同。

合起来就是网址负责找东西、请求方式负责做什么。这套东西下一篇开始真的用到，我要给猜字谜搭一个能新建一局的后端接口。
