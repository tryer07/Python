# 文字冒险RPG实战（2）状态行协议：让 AI 把血量吐成程序能读的一行字

> 这是系列的第二篇。上一篇结尾留了个钩子：我要求 AI 主持人每次回复的最后，必须另起一行吐这样的东西：`[状态] HP=60/100 攻击=13 物资=25 背包=开山刀,绷带x2`。这一篇就讲这行字：它为什么长这样、我怎么把它抠出来、AI 不听话的时候游戏为什么不能崩。

## 一、剧情归剧情，账必须归程序记

先说清楚我为什么不放心让 AI 自己管数值。

它的每次回复就是一段文字，文字里的 HP 说多少是多少，没有东西兜着。我试过让它在剧情里自己写"你还剩 60 点血"，玩到第十几回合，前文说过的数字就开始对不上：明明受过两次重伤，血还是满的。文字模型对"维护一个跨几百轮一致的状态"本来就不擅长，这不是提示词能根治的。

所以我把职责劈开了：AI 只负责判定和叙事，但必须把判定结果额外交一份机器可读的副本；程序拿到副本后把数字写进存档，前端的状态面板只认存档。游戏里真正的血量，永远是字典里那个 int，不是 AI 嘴里说的。

## 二、这行格式是怎么谈下来的

我最初的想法是让 AI 回复完剧情再输出一段 JSON，写了两轮就放弃了：它正沉浸在写小说，让它突然切换成序列化模式，大括号和引号经常丢三落四，一个字符错整段就解析不了。

于是我改成一行定制的单行格式，写进系统提示词的规则第 4 条：

```
4. 玩家每次行动后，你必须在回复的最末尾另起一行，用如下格式输出最新状态
   （这一行会被程序解析，格式绝不能错）：
   [状态] HP=数值/上限 攻击=数值 物资=数值 背包=物品1,物品2
   示例：[状态] HP=60/100 攻击=13 物资=25 背包=开山刀,绷带x2
   没有变化也要原样重复当前状态。背包为空时写 背包=无。
```

定这三个小规矩各有各的用意。`[状态]` 前缀是我在自己脑子里定的哨兵，剧情里不会出现这五个字符，正则拿它当锚很稳。给示例比给抽象格式管用得多，模型照抄样例的能力远强于理解文法的能力。"没有变化也要原样重复"是防它偷懒：缺了这一句，它有时会只回剧情不带状态行。

## 三、用正则把这行字抠出来

程序这边的搭档是一个编译好的正则：

```
STATUS_PATTERN = re.compile(
    r"\[状态]\s*HP=(\d+)/(\d+)\s*攻击=(\d+)\s*物资=(\d+)\s*背包=(.+)"
)
```

`search` 而不是 `match`，因为这行字前面还压着一整段剧情，我要在全文里找它。五个捕获组正好对应五个字段，`背包=(.+)` 贪婪吃到行尾，物品之间用逗号分隔。

## 四、解析成功之后做三件事

拿到 match 只是开始，`apply_status_to_session` 里我按顺序干了三件事：

```
def apply_status_to_session(session_data, reply_text) -> str:
    match = STATUS_PATTERN.search(reply_text)
    if not match:
        return reply_text

    hp, max_hp, attack, gold, items_text = match.groups()
    status = session_data["character"]["status"]
    status["hp"] = int(hp)
    status["max_hp"] = int(max_hp)
    status["attack"] = int(attack)
    status["gold"] = int(gold)
    items = [item.strip() for item in items_text.split(",")]
    status["items"] = [] if items == ["无"] else items

    clean_text = reply_text[: match.start()].rstrip()
    return clean_text
```

第一件，把数字转成 int 写回会话字典，这是唯一的入账时刻。第二件，处理背包这个特殊字段：`背包=无` 拆出来是 `["无"]`，得手动翻译回空列表，AI 那边约定了空背包就写"无"。第三件，把状态行从文本里切掉：`reply_text[: match.start()]` 只留剧情，这一行是给我看的，不该给玩家看。

返回值设计成"清洗后的展示文本"，接口拿它直接回给前端，一鱼两吃。

## 五、AI 不吐这一行怎么办

这是我最开始最怕的情况：玩到兴头上，模型忘了规矩，只回了剧情没有状态行。

我的处理朴素但有效：不报错，不改数值，原文返回。

```
    if not match:
        return reply_text
```

解析失败就当作这回合没有任何数值变化，玩家看到的是正常剧情，存档里血量保持上一回合的数。游戏绝不因为这行字缺席而中断。事后我观察，这种回合大约几十局碰上一两次，而且下一回合它看到自己上次的状态还在提示词里（第一篇讲的每回合现拼角色卡），基本都会自己续上规矩。

顺着还有一个细节：落盘的历史消息只存清洗后的剧情，状态行不进 `messages`。因为状态每次都是拼系统提示词时现给的，历史里留着一堆旧状态行，反而会干扰它，让它以为那些过期的数字还有参考价值。

## 六、账管住了，脑子还不够用

状态同步这条线到这里就闭环了：AI 判定、单行协议、正则抠取、程序入账、失败兜底。

但游戏再往下玩，另一个问题浮出水面。每回合历史都要原样喂回给 AI 续剧情，玩到三十回合， messages 里躺着六十条记录，AI 开始忘我第一篇里说的"伏笔要记得回收"，token 也跟着涨。直接砍掉老历史怕它断片，我想了个压缩的办法，那是下一篇的内容：前情摘要。
