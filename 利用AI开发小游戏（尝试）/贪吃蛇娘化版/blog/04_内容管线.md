# 一个 Python 新手，靠 AI 帮忙把贪吃蛇做成了"蛇娘"游戏（4/5）：没有一首 BGM 是音频文件

> 系列：《一个 Python 新手，靠 AI 帮忙把贪吃蛇做成了"蛇娘"游戏》共 5 篇。本篇讲一个没资源的新手，怎么搞定美术和音乐。
> 完整源码不公开；文中代码都是我学习用的简化版，直接复制跑不起来。

前三篇把架构、画面、战斗都讲完了。这一篇我想聊一个特别现实的问题：**作为一个既不会画画、又不懂音乐、还没钱买素材的新手，游戏里那些立绘、背景、音乐音效，到底从哪来？**

先说个可能让你意外的事实：**我这个游戏的 `assets` 文件夹里，压根没有 `audio` 目录，一个音频文件都没有。** 但你玩的时候，点击有"哒"声、升级有上行音阶、四张地图各有各的背景音乐——这些声音，全是程序在运行时**用代码当场"算"出来的**。

这一篇就讲两件事：**我怎么用 AI 出图、再用脚本把图切成素材；以及我怎么用 Python 合成全部音乐音效。** 后者是我整个项目里最"魔幻"、也最想分享的部分。

## 一、美术：AI 出图只是第一步，"能用"才是难点

我完全不会画画，这点没什么好藏的。角色立绘、场景背景，我全是用 AI 生成的。但一开始我天真地以为"AI 生成一张好看的图 = 素材搞定了"，结果发现差得远：

- AI 出的图**带着一整块背景**，可我要的是透明背景的角色；
- 有的图角落**带着 AI 平台的水印**；
- 尺寸、构图**参差不齐**，直接放进游戏大小不一；
- 最麻烦的是蛇身——AI 给的是一整条蛇，可贪吃蛇的身体需要能**一节一节拼接、还要能收窄成尾巴**。

我一开始是手动抠图，用画图软件一点点擦背景，擦到眼睛都花了，一个角色搞半天。后来我实在受不了，问 AI 有没有办法自动化。它说：这些操作（去背景、裁边、缩放）都能用代码批量做。于是我们一起写了一个切图脚本 `prepare_assets.py`。

---

## 二、切图管线：一个脚本，把 AI 原图批量变成游戏素材

这个脚本的思路，是我和 AI 约定了一套**命名规范**，然后让脚本按规范自动处理：

- 我把 AI 生成的原图，按 `{角色}_src_upper.png`（上半身）、`{角色}_src_scale.png`（鳞片/身体）、`{角色}_src_tail.png`（尾巴）、`{角色}_src_full.png`（全身立绘）命名，丢进一个目录；
- 脚本自动对每张图做：**去背景 → 去水印 → 自动裁掉多余空白 → 缩放到统一尺寸 → 柔化边缘**；
- 蛇身那张还会被特殊处理成**梯形条带**（一头宽一头窄），这样游戏里拼接身体时才能自然收窄到尾巴；
- 最后按 `{角色id}/head.png`、`body_seg.png`、`tail_tip.png`、`full.png` 输出。

这里面每一步我都是"知道要干什么、但不知道具体怎么写"，全靠 AI 教。比如"去背景"，我才知道原来有几种情况：背景是纯色的可以用"洪水填充"从边缘往里漫；背景是棋盘格的要按颜色容差判断。我把脚本里"自动裁掉空白"这一小段的意思简化一下，你就明白它有多朴素：

```python
# 教学简化版·非完整可运行·by 【你的CSDN_ID】
def autocrop(im, pad=6):
    """把图片四周的透明空白裁掉，只留下有内容的部分，再留一点边距。"""
    # 扫描每个像素，找出"不透明像素"的最小外接矩形 (l, t, r, b)
    l, t, r, b = 找非透明区域的边界(im)
    # 按这个矩形裁一刀，四周各留 pad 像素
    return im.crop((l - pad, t - pad, r + pad, b + pad))
```

有了这个脚本，我后来加新角色时，只要把 AI 出的四张原图按规范命名丢进去，跑一下脚本，素材就齐了——**再也不用手动抠图抠到崩溃**。这大概就是"把重复劳动交给代码"的快感吧，虽然我一开始是被逼的。

## 三、数据驱动：一个角色，其实就是一份 JSON

美术搞定后，角色的"信息"放哪？还是老规矩——**JSON**。第一篇提过"加角色不改代码"，这一篇把这份配置摊开看。

一个角色在 `characters.json` 里是这么一条（我节选了初始角色"樱落"，删了一些长文本）：

```json
{
  "id": "sakura",
  "name": "樱落",
  "rarity": "SSR",
  "title": "樱花神域的守护者",
  "element": "樱",
  "growth": "均衡",
  "desc": "来自樱花神域的蛇娘，性格温柔。等级越高，斩击越锋利。",
  "story": "樱落诞生于樱花神域最深处的古树之下……（这里是一大段角色背景故事）",
  "egg_lines": {
    "head": ["哎呀…被你摸到头了呢，花瓣都乱了。"],
    "body": ["腰这里…是鳞片开始的地方，痒痒的。"],
    "tail": ["尾巴是我的骄傲，轻一点哦。"]
  },
  "kit": {
    "actives": [
      {"id": "petal_slash", "type": "petal_slash", "name": "落樱·绯斩",
       "key": 1, "color": [255, 150, 190], "vfx": "slash",
       "desc": "向前突进斩击，路径敌人受伤，并获得短暂护盾。"}

  },

  "body_seg": "characters/sakura/body_seg.png",
  "tail_tip": "characters/sakura/tail_tip.png"
}
```

这份配置里，藏着我作为一个"什么都要自己来"的新手的一点小心思：

- **`story` 和 `desc`**：给角色写背景故事和人设。虽然没人规定贪吃蛇要有剧情，但我觉得有故事的角色才"活"；
- **`egg_lines`**：这是我特别得意的一个小设计——玩家在角色详情页摸头、摸腰、摸尾巴，会触发不同的台词彩蛋。这些台词也全在 JSON 里，我想加就加；
- **`kit.actives` 里的 `color` 和 `vfx`**：`color` 是这个角色技能特效的配色，`vfx` 是特效样式（slash 斩击 / star 星芒 / wave 波纹…）。**六个角色共用同一套连招机制（第 3 篇讲的），靠这两个字段就长出了各自不同的视觉风格**；
- **`desc`**：每个技能的一句话说明，角色详情页直接读它显示，所以我又给每个技能都写了介绍。

对我这种新手来说，把内容全塞进 JSON 最大的好处是：**我想加角色、改台词、调配色，都不用去碰那堆我看着就头疼的战斗代码**，改完 JSON 存盘就生效。

## 四、重头戏：没有一首 BGM 是音频文件，全用代码"算"出来

好，来到这篇我最想讲的部分。

我最初的认知和大多数人一样：**游戏音乐 = 一堆 mp3/ogg 文件。** 可问题来了——我没有音乐素材，网上下的又有版权风险，我自己更不会作曲。我甚至一度想让游戏"静音"算了。

是 AI 给我打开了一扇窗。它说了一句我至今记得的话：**"声音的本质就是一条波形的曲线，而曲线是可以用数学算出来的。你没有音频文件，但你可以用代码把波形一个点一个点地算出来。"**

我半信半疑，但它真的带我一步步做出来了。核心其实就四个小函数，我把它们理解成"作曲的四块积木"：

### 积木一：`_tone()` —— 算出"一个音"

一个音，本质就是让空气按某个频率振动。代码里就是**逐个采样点算正弦值**：

```python
# 教学简化版·非完整可运行·by 【你的CSDN_ID】
def _tone(freq, dur, wave="sine", vol=0.5, slide_to=None):
    """算一段单音，返回一串 [-1, 1] 之间的采样点。"""
    n = int(dur * SAMPLE_RATE)          # 这段音一共有多少个采样点
    out, phase = [0.0] * n, 0.0
    for i in range(n):
        p = i / n
        # 频率可以从 freq 平滑滑到 slide_to，就做出"滑音"效果
        f = freq if slide_to is None else freq + (slide_to - freq) * p
        phase += 2 * math.pi * f / SAMPLE_RATE
        v = math.sin(phase)             # 正弦波；换个数学公式就是方波/三角波/锯齿波
        # …再乘一段"渐强渐弱"的包络，避免开头结尾"啪"地爆音…
        out[i] = v * vol
    return out
```

我当时连"采样率""波形""包络"这些词都是第一次听，是 AI 一个个给我解释：采样率就是"一秒取多少个点"，点越密声音越细腻；正弦波听着柔和、方波听着电子、锯齿波听着粗糙；包络就是"让声音慢慢起来、慢慢消失"，不然会有爆音。懂了之后，我发现调这几个参数就能调出完全不同音色的音，特别有意思。

### 积木二和三：`_seq()` 拼旋律，`_mix()` 叠和声

有了单个音，把它们**一前一后接起来**就是旋律，**同时叠起来**就是和声：

```python
# 教学简化版·非完整可运行·by 【你的CSDN_ID】
def _seq(segments):        # 顺序拼接：一个音接一个音 → 旋律
    out = []
    for s in segments:
        out.extend(s)
    return out

def _mix(tracks):          # 叠加多轨：几个音同时响 → 和声
    n = max(len(t) for t in tracks)
    out = [0.0] * n
    for t in tracks:
        for i, v in enumerate(t):
            out[i] += v
    return out
```

最后再用 `_to_bytes()` 把这串 `[-1, 1]` 的数字转成 pygame 能播放的 16-bit 字节流，一个音就做好了。

### 用积木拼出音效

有了这四块积木，各种音效就是"配方"问题了。我截几个真实的例子：

```python
# 教学简化版·非完整可运行·by 【你的CSDN_ID】
# 点按钮：又高又短的方波，"哒"
"ui_click": _tone(1200, 0.04, "square", 0.32)

# 升级：Do-Mi-Sol-Do 四个音依次上行，一听就是"升级了"
"level_up": _seq([_tone(N[k], 0.07, "sine", 0.38)
                  for k in ("C5", "E5", "G5", "C6")])

# 受伤：低频方波往下滑 + 一点噪声，闷闷的"咚"
"hurt":     _mix([_tone(110, 0.15, "square", 0.36, slide_to=70),
                  _noise(0.15, 0.22)])
```

（上面的 `N["C5"]` 是一个"音名 → 频率"的字典，`_noise()` 是生成噪声的积木，用来做打击感。）

### 用积木拼出 BGM：四张地图，四首不同的曲子

背景音乐比音效复杂一点，但思路一样。我给每个场景配一组**"和弦走向 + 音色 + 速度"**，然后让代码把它渲染成"高音琶音 + 低音铺底"叠在一起的循环：

```python
# 教学简化版·非完整可运行·by 【你的CSDN_ID】
if name == "battle_campus_garden":      # 校园庭院：明亮大调、中速、正弦波
    chords = [("C4","E4","G4"), ("G3","B3","D4"), ("A3","C4","E4"), ("F3","A4","C4")]
    note_dur, wave = 0.20, "sine"
elif name == "battle_deep_sea":         # 深海遗迹：低八度、慢速、三角波，幽深压迫
    chords = [("D3","F3","A3"), ("C3","E3","G3"), ("D3","F3","A3"), ("E3","G3","B3")]
    note_dur, wave = 0.30, "tri"
# …霓虹夜市用小调方波（紧张）、樱花神域用高音颤音（空灵），各有各的配方…

# 把和弦拆成"高音琶音 lead + 低音铺底 bass"，叠起来就是一段 BGM
lead = []
for (a, b, c) in chords:
    for f in (a, b, c, b):
        lead.extend(_tone(N[f], note_dur, wave, 0.15))
bass = []
for (a, _b, _c) in chords:
    bass.extend(_tone(N[a] / 2, note_dur * 4 * 0.9, "sine", 0.11))
return _mix([lead, bass])
```

四张地图就这样有了四首听感明显不同的曲子，全程没有用到任何一个音频文件。

### 我还留了一手：以后想换真音乐，丢文件进去就行

虽然我现在全靠合成，但 AI 提醒我别把路走死。所以我们设计成"**混合素材**"：程序会先去 `assets/audio/bgm/` 找有没有对应的真实音频文件（`.ogg`/`.wav`/`.mp3`），**有就用真文件，没有才用代码合成兜底**。

也就是说，将来我哪天找到了一首心仪的、没有版权问题的曲子，只要把文件按约定的名字丢进那个目录，游戏就会自动用它替换掉合成音——**一行代码都不用改**。这个"留后路"的设计，是我从这个项目里学到的另一个重要习惯。

## 五、这套思路，让一个"三无新手"也撑起了一个游戏

回头看，我既没美术、也没音乐、也没预算，能把这个游戏做成现在这样，靠的就是两条：

1. **内容数据驱动**：角色、场景、技能、台词全在 JSON 里，加内容不碰代码；
2. **素材程序生成**：图靠 AI + 脚本切，声音靠代码合成，绕开了"没有资源"这个死结。

这两条合起来，让我一个人也能撑起一个有 6 个角色、4 张地图、几十种音效和 4 首 BGM 的游戏。**对和我一样"什么都不会、但想做点东西"的新手来说，我觉得这比任何具体代码都更值得记住：资源不够，就用思路来凑。**

当然，这一篇里的合成代码，绝大部分是 AI 写的，我更多是"听懂原理、然后敢改参数"。我不敢说这些代码写得多专业，但至少它跑起来了，还挺好听。
